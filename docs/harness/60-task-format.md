# 60 — タスクの様式

**法 1（タスク先行）の本体。**

## 1. どこにあるか

| 場所 | 中身 |
|---|---|
| [docs/tasks/backlog.md](../tasks/backlog.md) | **台帳。** 全タスクの 1 行サマリと状態。これが唯一の進捗管理表 |
| `docs/tasks/<ID>-<slug>.md` | **タスク詳細＝実装計画。** 複数ファイルに跨る変更では必須 |
| [templates/task.md](./templates/task.md) | タスク詳細の様式 |

## 2. ID の採番

`T` + 3 桁連番。**台帳にある最大値 +1**。欠番があっても埋めない。**ID は再利用しない。**

`slug` は英小文字とハイフン（`T101-dispose-pattern-cleanup`）。

## 3. 状態

| 記号 | 状態 | 意味 |
|---|---|---|
| `[ ]` | 未着手 | 起票済み。まだ手を付けていない |
| `[~]` | **進行中** | 現在作業中。**原則として同時に 1 件だけ** |
| `[x]` | 完了 | 品質ゲート G1/G2/G3 を通し、実測値を記録済み |
| `[-]` | 取り下げ | 実施しないと決めた。理由を 1 行添える |

遷移は `[ ] → [~] → [x]` または `[ ] → [-]`。

> **`[~]` が 1 件も無い状態で `.cs` / `.xaml` を編集しようとすると
> `guard-source-edit.ps1` が確認を求める。** これが「タスク先行」の強制点。

## 4. 台帳の書式

```markdown
## 進行中

- [~] **T101** Dispose パターンの是正（CA1063/CA1816/CA1001/CA2213/CA2000） → [詳細](./T101-dispose-pattern-cleanup.md)

## 未着手

- [ ] **T102** カルチャー明示の是正（CA1305/CA1307）

## 完了

- [x] **T100** 開発ハーネスの整備 (2026-08-14) → [詳細](./T100-dev-harness.md)
```

- 行の形式は `- [状態] **<ID>** <一言サマリ>`（必要なら ` → [詳細](./<ID>-<slug>.md)`）。
- 完了時は `(YYYY-MM-DD)` を添える。
- セクション（進行中／未着手／完了）をまたいで **行を移動** させる。行を複製しない。

## 5. 粒度

**1 タスク＝1 つの目的。** 判断基準：

- 完了条件を 1 文で言い切れるか → 言い切れないなら分割する
- ゲート（G1/G2/G3）を 1 回通せば終わるか → 何回にも分かれるなら分割する
- 独立して差し戻せるか → まとめると片方だけ戻せないなら分割する

**分割しすぎない基準：** 単独で意味を成さない断片（「メソッドの引数を追加する」だけ等）は
親タスクの中の 1 ステップであって、独立したタスクではない。

## 6. タスク詳細に必ず書くこと

様式は [templates/task.md](./templates/task.md)。省略してよいのは「1 ファイルの些細な変更」のときだけ
（その場合は台帳の 1 行で足りる）。

| 項目 | なぜ要るか |
|---|---|
| **目的** | 何のためか。1〜2 文 |
| **スコープ境界** | 何を変え、**何を変えないか**。変えないほうを太字で書く。スコープ膨張の防止線 |
| **決定事項** | 実装中に蒸し返さないために固定した選択。ID 付き（`D1`, `D2`…）で参照可能にする |
| **仕様書への影響** | 更新する章、または「仕様非影響」と明記した理由 |
| **アーキテクチャへの影響** | ADR が必要か。不要ならその理由 |
| **変更ファイル一覧** | パスと変更内容。実装前に洗い出す |
| **テスト一覧** | 追加・変更するテストメソッド名と、それが保証すること |
| **未解決の質問** | 事実ではなく **判断** を要するもの。既定案を添えて確認する |
| **実行結果** | 完了時に G1/G2/G3 の **実測値** を記録する |

## 7. 完了の条件

以下を **すべて** 満たしてはじめて `[x]` にできる。

1. タスク詳細に書いたスコープを満たしている（それ以上でも以下でもない）
2. 品質ゲート G1 / G2 / G3 が **すべて緑**（[40-quality-gates.md](./40-quality-gates.md)）
3. 仕様書への影響がある場合、`docs/spec/` を更新済み
4. タスク詳細の「実行結果」に **実測値** を記録済み
5. 台帳の行を「完了」セクションへ移動し、日付を記入済み

**片付いていないものを `[x]` にしない。** 途中で止めるなら `[~]` のまま、残りを本文に書き残す。
