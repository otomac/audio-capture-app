# T146 — 短い話者区間の埋め込みが安定しない問題（原因を数で確定させ、今回は現状維持）

> **状態:** 完了 — 2026-08-23
> **台帳:** [docs/tasks/backlog.md](./backlog.md)
> **関連:** [T138](./T138-speaker-id-fragmentation.md)（発見元）／[T142](./T142-diarization-attribution-root-cause.md)／
> [ADR-0003](../adr/0003-speaker-diarization-with-sherpa-onnx.md)／
> **[ADR-0004](../adr/0004-speaker-id-assignment-strategy.md)（本タスクで起票）**／T148（後継）

## 1. 目的

T138 は「話者 ID の断片化の原因は、閾値でも埋め込みモデルでもなく**短い区間の埋め込みが
安定しないこと**」と結論した。ただしそれは**間接的な観察**（ID ごとの発話時間の分布）からの
推論であり、埋め込みそのものを測ってはいない。
**原因を直接測って確定させ、打ち手があるかを判断する。**

## 2. 結論

**原因は確定した。今回はソースを変更しない（現状維持）。**

1. **仮説は正しい。埋め込みの安定性は切り出し長で決まる**（§7-1）。
   同一話者の埋め込みどうしの類似度は **0.25 秒で 0.31 → 1 秒で 0.51 → 3 秒で 0.76 → 10 秒で 0.90**。
   一方、別話者どうしは長さによらず 0.22〜0.44 に留まる。
   **既定のクラスタリング閾値 0.5 は、ちょうど「1 秒の区間の同一話者類似度」に一致する** —
   つまり **1 秒の区間は、同じ人でも半分は別クラスタへ弾かれる。**
   T138 が観測した「区間長の中央値 1.03 秒・1 秒未満が 50%」という分布と正確に噛み合う。
2. **だが、断片化は問題の半分でしかない。** 正解が全区間で分かる合成音声で測ると、
   **短い交代（中央値 1.2 秒）の音声では話者交代そのものが 9% しか検出されず**、
   正答率は 51.4%（＝当て推量）である（§7-2）。埋め込みを改善しても、
   区間が生成されていない以上どうにもならない（T142 ①と同じ壁）。
3. **出力の後処理（短い区間の ID を隣へ寄せる）は、費用に見合わない**（§7-3）。
   行に付く ID は会議 A で 72 → 70、会議 B で 36 → 31 しか減らず、
   正答率は 92.0% → 92.2%（誤差の範囲）。動く行は 6〜16 行あるが、
   それが良くなったのかを確かめる材料が無い。
4. **話者 ID を自前で付け直す試作は、測った範囲では明確に良い**（§7-4）。
   sherpa-onnx からは**話者区間の時刻だけ**を受け取り、
   3 秒以上の区間だけで凝集型クラスタリングを行い、短い区間はその重心へ寄せる。
   基準音声で **使用 ID 6 → 2（実際の人数）を、正解 4 箇所の区別を 4/4 保ったまま**達成した。
   T115 以降で**「ID の数」と「区別」の両方が同時に良くなった初めての構成**である。
   **しかし今回は採用しない** — 判断の材料が足りないためである。理由と採用条件は
   [ADR-0004](../adr/0004-speaker-id-assignment-strategy.md) に書いた。後継は **T148**。

## 3. スコープ境界

**やったこと**

- 埋め込みの安定性を切り出し長ごとに直接測る
- 正解が全区間で分かる合成音声を作り、話者交代の検出率と正答率を測る
- 出力の後処理（4 種類）を実データで採点する
- 自前で ID を付け直す試作を作って採点する

- **埋め込みモデルは変えない。** T138 で 4 種を実測済み（既定以外はすべて区別を失う）。
- **segmentation モデルは変えない。** T142 / T144 の範囲。
- **sherpa-onnx のバージョンは上げない。** 1.13.6 が出ているが本タスクとは無関係。

## 7. 実測

### 7-1. 埋め込みは何秒から安定するか

同じ録音から長さ `L` の断片を等間隔に 40 個取り、埋め込み（既定の campplus zh_en advanced）を計算して
コサイン類似度を比べた。「同一話者」は同じ録音の断片どうし、「別話者」は別の録音の断片どうしである。
材料は単独話者の録音 2 本（3 分 00 秒 / 8 分 34 秒）。

| 切り出し長 | 同一話者の類似度（平均・10〜90 パーセンタイル） | 別話者の類似度 | 判別できる割合 |
|---|---|---|---|
| 0.25 秒 | **0.308** (0.108〜0.568) | 0.245 (0.072〜0.539) | **62.9%** |
| 0.50 秒 | **0.345** (0.164〜0.525) | 0.216 (0.091〜0.350) | **77.4%** |
| 0.75 秒 | 0.434 (0.248〜0.615) | 0.235 (0.108〜0.362) | 86.9% |
| **1.00 秒** | **0.513** (0.327〜0.682) | 0.250 (0.145〜0.362) | 92.9% |
| 1.50 秒 | 0.636 (0.498〜0.761) | 0.303 (0.194〜0.412) | 99.1% |
| 2.00 秒 | 0.697 (0.561〜0.812) | 0.341 (0.231〜0.449) | 98.1% |
| 3.00 秒 | 0.761 (0.654〜0.861) | 0.366 (0.276〜0.457) | 99.9% |
| 5.00 秒 | 0.840 (0.758〜0.908) | 0.404 (0.313〜0.490) | 100.0% |
| 10.00 秒 | 0.904 (0.835〜0.949) | 0.441 (0.379〜0.498) | 100.0% |

（「判別できる割合」＝ 同一話者ペアの類似度が別話者ペアの類似度より高い確率。50% が当て推量）

**読み取れること。**

1. **同一話者の類似度は切り出し長とともに単調に上がるが、別話者の類似度はほとんど動かない。**
   つまり短い区間で失われているのは「別人を遠ざける力」ではなく「同一人物を近づける力」である。
   **これが断片化（同じ人が別 ID になる）の直接の原因である。**
2. **既定のクラスタリング閾値 0.5 は、ちょうど 1 秒の区間の同一話者類似度（0.513）と同じ高さにある。**
   T138 が観測した基準音声の区間長（中央値 1.03 秒・1 秒未満が 50%）を当てはめると、
   **半分の区間は同一人物でも閾値を越えられない。** 断片化はこの帰結である。
3. **0.25〜0.5 秒では別話者との差がほとんど無い**（判別 62.9〜77.4%）。
   この長さの区間に付いた話者 ID は、ほぼ根拠が無いと考えてよい。
4. **3 秒あれば実用上ほぼ完全に分かれる**（判別 99.9%、同一 0.761 対 別 0.366）。
5. **閾値を下げれば直る問題ではない。** 0.25〜0.5 秒では同一話者と別話者の分布が
   ほぼ完全に重なっており、どこで切っても正しく分けられない。
   T138 が閾値 0.4〜0.7 で ID 数が動かなかったことの説明になっている。

### 7-2. 正解が全区間で分かる合成音声

単独話者の録音 2 本を交互につないだ音声を 3 本作った（交代の間に 0.15 秒の無音。
話者ごとの音量差で区別できてしまわないよう RMS をそろえた）。

| 音声 | 長さ | 交代 | 交代の長さ | 生成 ID | 正答率 | 話者交代の検出率（±0.25 秒） |
|---|---|---|---|---|---|---|
| 長短混在 | 350.7 秒 | 38 | 1〜25 秒（中央値 7.0） | 3 | **92.0%** | 38% |
| 長い交代のみ | 362.7 秒 | 18 | 12〜30 秒（中央値 20.0） | 4 | **97.5%** | 65% |
| 短い交代のみ | 396.5 秒 | 238 | 0.5〜3 秒（中央値 1.2） | 4 | **51.4%** | **9%** |

**短い交代の音声では、話者ダイアライゼーションは当て推量と同じである。**
238 回の交代に対して生成された話者区間はわずか 31 本で、交代の 91% が検出されていない。
これは埋め込みの問題ではなく **segmentation が話者交代を出していない**ためであり、
T142 ①（相槌に話者区間が生成されない）を正解付きで再現したことになる。

**つまり短い発話の話者を当てる方法は、埋め込み側にもクラスタリング側にも無い。**
T146 の起票時の見立て（打ち手は「短い区間の埋め込みをどう扱うか」）は、
**断片化には当てはまるが、相槌の取りこぼしには当てはまらない。**

区間そのものの質も測った（正解に対する純度）。

| 音声 | 区間 | 純度 100% の区間 | 純度の中央値 | 2 名にまたがった時間の割合 |
|---|---|---|---|---|
| 長短混在 | 46 | 30 | 100.0% | 7.6% |
| 長い交代のみ | 36 | 28 | 100.0% | 2.5% |
| 短い交代のみ | 31 | 17 | 100.0% | **46.6%** |

短い交代の音声では、**生成された区間の時間の半分近くが 2 人にまたがっている。**

### 7-3. 出力の後処理（案 B）

sherpa-onnx が返した話者区間の ID を、後から付け替える規則を 4 種類試した。

**基準音声（正解の分かる 4 箇所）:**

| 規則 | 生成 ID | 使用 ID | 区別 | 動いた行 |
|---|---|---|---|---|
| 何もしない | 16 | 6 | **4/4** | — |
| 0.5 秒未満の区間を隣の ID へ | 15 | 6 | 4/4 | 0 |
| 1.0 秒未満の区間を隣の ID へ | 9 | 6 | 4/4 | 0 |
| 1.5 秒未満の区間を隣の ID へ | 5 | 5 | **2/4** | 2 |
| 合計 2 秒未満の ID を近くの ID へ | 7 | 5 | **3/4** | 1 |

**会議 2 本（正解なし）— 行に付いた ID の数:**

| 音声 | 何もしない | 0.5 秒未満 | 1.0 秒未満 | 1.5 秒未満 | 合計 2 秒未満 |
|---|---|---|---|---|---|
| 会議 A（328 行） | 72 | 73 | 70 | 68 | 66 |
| 会議 B（229 行） | 36 | 34 | 31 | 27 | 26 |

**合成音声の正答率:** 長短混在 92.0% → 92.1〜92.2%（1.5 秒以上を寄せると 91.8% に低下）。

**採用しない。** 安全な範囲（1.0 秒未満まで）では**利用者が目にする ID の数がほとんど減らない**
（会議 A で 72 → 70）。減る設定（1.5 秒以上）は基準音声の区別を壊す。
正答率は動かない。**得るものが小さく、確かめられない変更が入る。**

### 7-4. 話者 ID を自前で付け直す試作（案 C）

sherpa-onnx からは**話者区間の時刻だけ**を受け取り、ID の決定を自前で行う。

1. 各区間の埋め込みを `SpeakerEmbeddingExtractor`（sherpa-onnx の既存 API・依存の追加なし）で計算する
2. **3 秒以上の区間だけ**で凝集型クラスタリング（平均連結・コサイン類似度 0.60 で打ち切り）
3. 3 秒未満の区間は自分でクラスタを作らず、できた重心のうち最も近いものへ寄せる

§7-1 の測定がそのまま設計になっている — **3 秒あれば判別率 99.9%、1 秒では 92.9%、
0.5 秒では 77.4%** なのだから、クラスタを作る権利は 3 秒以上の区間にだけ与える。

| 音声 | 実際の話者 | 既定 | 付け直し | 判定 |
|---|---|---|---|---|
| 基準（2 分 42 秒） | 2 名 | 使用 6 ID / 区別 **4/4** | 使用 **2 ID** / 区別 **4/4** | **良い** |
| 合成・長短混在 | 2 名 | 3 ID / 正答率 92.0% | **2 ID** / **92.4%** | **良い** |
| 合成・長い交代 | 2 名 | 4 ID / 97.5% | **2 ID** / 97.5% | **良い** |
| 合成・短い交代 | 2 名 | 4 ID / 51.4% | 1 ID / 51.1% | 変わらず（どちらも当て推量） |
| 単独 A（3 分 00 秒） | 1 名 | 1 ID | **1 ID** | 壊れない |
| 単独 B（8 分 34 秒） | 1 名 | 1 ID | **1 ID** | 壊れない |
| 会議 A（15 分 47 秒） | 不明 | 生成 108 / 使用 72 | **20** | 判定不能 |
| 会議 B（15 分 00 秒） | 不明 | 生成 45 / 使用 36 | **13** | 判定不能 |

処理時間の増加は **基準音声で +2.1 秒、会議 A（15 分 47 秒・322 区間）で +12.0 秒**
（Diarization 本体はそれぞれ約 20 秒 / 約 130 秒）。**約 1 割の増加で済む。**

**測った範囲では、T115 以降で初めて「ID の数」と「区別」が同時に良くなった構成である。**
それでも今回採用しないのは、しきい値の安全域が狭いからである。
打ち切りに使うコサイン類似度について、実測 6 本での安全域は次のとおりだった。

| 音声 | 同一話者として併合された最後の類似度 | 別話者として拒否された最初の類似度 |
|---|---|---|
| 基準 | 0.653 | 0.275 |
| 合成・長短混在 | 0.784 | 0.532 |
| 合成・長い交代 | 0.782 | 0.472 |
| 単独 A | 0.990 | （なし） |
| 単独 B | 0.875 | （なし） |
| 合成・短い交代 | 0.875（実際は別話者。区間が混ざっているため） | （なし） |

**安全に切れる範囲は 0.53〜0.65 の幅 0.12 しかない。** 採用した 0.60 の余裕は
上側 0.053・下側 0.068 である。外した側の壊れ方は非対称で、
**高すぎれば ID が増えるだけ（今と同じ）だが、低すぎれば全員が 1 人にまとまる**（沈黙的な誤り）。
実際、当初試した 0.50 では合成・長短混在が 1 ID に潰れ、正答率 92.0% → 52.2% になった。

判断は [ADR-0004](../adr/0004-speaker-id-assignment-strategy.md) に記録した。

## 9. 未解決の質問（申し送り）

1. **案 C を採るかどうか。** → **T148** として起票した。採用条件は ADR-0004 に書いた。
2. **相槌・短い割り込みには依然として打ち手が無い。** §7-2 のとおり、
   segmentation が交代を出さない以上、後段で何をしても届かない。→ T144（条件付きで再評価）。
3. **合成音声は本物の会議ではない。** 別々の録音をつないでいるため、
   録音条件（マイク・部屋・音量）の違いが話者の違いとして働いている可能性がある。
   本物の 2 名対話（基準音声）でも同じ傾向が出ていることは確認したが、
   **合成音声の正答率をそのまま実力と読んではいけない。**

## 10. 計測方法（再現手順）

1. `embstab`（本タスクで追加） — 長さを変えた断片の埋め込み類似度を測る（§7-1）
2. `synth`（T147 で追加） — 正解付きの合成音声を作る（§7-2）
3. `diarize` — 話者区間を JSON へ書き出す
4. `recluster`（本タスクで追加） — 区間の時刻だけを使って ID を付け直す（§7-4）
5. `merge` — 本体の `TranscriptDiarizationMerger.Merge` で行へ話者を付ける
6. Python で採点する（基準音声は 4 箇所の区別、合成音声は正答率）
