# T182 — 速報パスの実測と方式の決定（ADR-0007 の確定）

> **状態:** 完了 — 2026-10-11（2026-10-05 着手。実施条件は 2026-10-04 に確定。§3 / §9）。案 B で ADR-0007 を承認済みにした
> **台帳:** [docs/tasks/backlog.md](./backlog.md)

## 1. 目的

[ADR-0007](../adr/0007-two-pass-live-transcription.md) の速報パスをどこで回すか（案 A: GPU で確定パスと直列／案 B: CPU の別スレッドで並列）を、
**Zoom 会議中の実機**で測って決める。決めた方式で ADR-0007 を承認済みにし、[T181 §11](./T181-two-pass-live-transcription-design.md#11-仕様変更の提案) の仕様変更を `docs/spec/` へ反映する。

## 2. スコープ境界

**やること**
- 使い捨ての計測ハーネスで M1〜M6（§4）を測る
- 速報用モデル（tiny / base）・`audio_ctx` の方針・間隔と duty の既定値・文脈プロンプトの採否を決める
- ADR-0007 の「決定」を確定させて承認済みにする。`docs/spec/`（01 / 02 / 04）へ反映する

**やらないこと（重要）**
- **計測ハーネスをリポジトリに入れない**（ローカルの作業用フォルダに置く。T142 と同じ扱い）
- **アプリ本体のコードを変えない**（実装は T185 以降）
- **確定パスの区切り方（REQ-TRX-LIVE-04 / 10 / 12 / 13）を変えない** — 計測で遅れが見つかっても、それは T183 か別タスクで扱う

## 3. 実施場所

**利用者の手元の Windows 機**（RTX 3050 6GB / Vulkan / 20 コア。T175 と同じ機械）で行う（2026-10-04 に確定）。
クラウド環境には dotnet も GPU も無いので、ここでは測れない。手元の Claude Code セッションに本書を渡して進めてよい。

**2026-10-04 に決まったこと:**

- **GPU は Vulkan だけで測る。CUDA は測らない**（§9-2）。
- **Zoom の相手は自分 1 人の会議**。「カメラ ON」→「カメラ ON ＋仮想背景」の 2 条件で測る（§9-1）。
- **Zoom の置き場所。** この機械には GPU が 2 つあり、Zoom をどのディスプレイ（＝どの GPU が描画するか）に置くかで
  遅れ方が変わることを利用者が観察している（Whisper と同じ GPU が担当するディスプレイに置くと遅れる）。
  **M4 は Zoom を RTX 3050 が担当するディスプレイに置いて測る（厳しい側）。** どのディスプレイ・どの GPU だったかを
  「実測結果」に記録する（タスクマネージャーの詳細タブの「GPU エンジン」列で確かめる）。

- ハーネス: .NET 10 のコンソールアプリ。`Whisper.net` / `Whisper.net.Runtime` / `.Cuda` / `.Vulkan` を**アプリと同じ 1.9.0** で参照する。
  ランタイムの読み込み順は Vulkan → CPU に固定する（CUDA を測らないため。アプリは CUDA → Vulkan → … の順だが、
  この機械では T175 以来 Vulkan が選ばれている）
- 確定パスは**今の `develop` の区切り方を再現する**: チャンクの上限は遅れていないとき 10 秒、遅れているとき
  （全ソースの滞留 60 秒分以上）20 秒（T190）。遅れの判定は全ソースの滞留で行い、ギャップ分割も 20 秒で区切る（T183）。
  ハーネスは本体の `internal` な純粋関数（`TakeNextChunk` / `ChunkTakeCount` / `SplitVoicedRegions` など）をそのまま呼んで、本体とずれないようにする
- 音声: T175 で使った実録音 2 本（62.7 分・15.8 分の会議）。16kHz モノラルへの変換はアプリと同じ手順（`TranscriptionService.DownmixResampleAppend` 相当）で行う
- 比較の基準にする文: 同じ音声を `ggml-large-v3-turbo` でファイル文字起こしした結果
- 負荷の記録: `nvidia-smi --query-gpu=utilization.gpu,memory.used --format=csv -l 1`、タスクマネージャー（または `typeperf`）の CPU、Zoom の「統計情報」（フレームレート）
- GPU ドライバーのリセットの記録: 各計測の後に、信頼性モニター（`perfmon /rel`）の LiveKernelEvent と、イベントログ（Windows ログ → システム）の発生元 `nvlddmkm` / `Display` のエラーを確認する（2026-09-28 の事象。ADR-0007「背景」）

## 5. 合格線（ADR-0007「決定」の表と同じ。Zoom 会議中に測る）

| 指標 | 合格線 |
|---|---|
| 速報の遅れ（発話 → 画面） | p50 ≤ 1.2 秒、p95 ≤ 2.0 秒 |
| 確定パスの処理能力 | 速報なしの 90% 以上 |
| `PendingSeconds`（30 分） | 増え続けない（遅れの警告 REQ-REC-07 が出ない） |
| クラッシュ | 0 件 |
| GPU ドライバーのリセット | 0 件（信頼性モニター（`perfmon /rel`）に LiveKernelEvent が出ない。イベントログ（システム）に発生元 `nvlddmkm` / `Display` のエラーが出ない） |
| Zoom の映像 | フレーム落ち 10% 以下、目に見えるカクつき無し |
| アプリの CPU 使用率 | 全コアの 25% 以下 |
| MP3 | 音飛び無し（ハーネスでは測れないので、T186 以降の実アプリで確かめる） |

**速報の質（M2）は合否に使わない**（利用者の前提は「精度は問わない」）。ただし、文字誤り率が 50% を超えて読めないなら tiny ではなく base を選ぶ。base でも読めなければ、ADR-0007 の案 D を利用者に再提案する。

### 計測の方法（ハーネスの定義）

ハーネスはリポジトリの外（`C:\personal\dev\audio-capture-work\t182\harness\`）に置いた .NET 10 のコンソールアプリ。

| 幻聴の除去（D11） | 正規化（NFKC・文字と数字だけ）後に空／定型句（「ご視聴ありがとうございました」等）だけ／同じ 2〜8 文字が 4 回以上連続（1 文字なら 8 回）・同じ語句が全体の半分以上、を「壊れた出力」として表示しない |
| 速報の間隔（D12） | 既定 1 秒。次の間隔 = clamp(その tick で速報に使った時間 ÷ duty 上限, 1 秒, 4 秒)。2 音源で 1 つの予算を分け合う |
| 案 A | 確定と同じスレッドで、GPU の速報用モデル（2 つ目の Vulkan コンテキスト）を使う。速報の期限が来ていれば、確定チャンクの**合間**に差し込む。遅れているとき（全ソースの滞留 60 秒分以上）は速報を飛ばす |
| 案 B | 別スレッド `ProvisionalTranscription`（`BelowNormal`）で、`UseGpu = false` の速報用モデル・4 スレッド |
| 速報の遅れ | 有声窓（100ms）ごとに「その窓を含む速報が最初に通知された時刻 − 窓の終わりの時刻」。壊れた出力は通知に数えない。通知されなかった有声窓は割合で別に出す。画面への反映（Dispatcher）の分は含まない |
| 確定の遅れ | 確定行の通知時刻 − その区間の終わり |
