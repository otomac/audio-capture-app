# T181 — ライブ文字起こしの 2 段化（速報 → 確定で置き換え）の設計

> **状態:** 完了 — 2026-09-27（設計の提案まで。ADR-0007 は提案中、仕様書本体への反映は T182）
> **台帳:** [docs/tasks/backlog.md](./backlog.md)

## 1. 目的

Zoom の字幕のように、話している最中から粗い文字（速報）をほぼリアルタイムに出し、後から文脈を踏まえた確定文で置き換える。
その設計を決め、実測の手順と後続タスクへの分け方を固める。**GPU（Vulkan / CUDA）環境で、Zoom 会議中も実用的な性能を保つことが必須条件**（利用者の依頼、2026-09-27）。

## 3. 決定事項

実装中に蒸し返さない。変えるときは本セクションと ADR-0007 を先に直す。

| # | 決定 | 結論 |
|---|---|---|
| D1 | 全体の形 | **速報パスと確定パスの 2 段。** 確定パスは今の仕組み（区切り方 REQ-TRX-LIVE-04 / 10 / 12 / 13、停止時の吐き切り REQ-TRX-LIVE-11）のまま |
| D2 | 速報のエンジン | **Whisper の軽量モデル（tiny / base）。** 登録済みモデル（REQ-CFG-08）から選ぶ。sherpa-onnx は採らない（利用者の判断。ADR-0007 案 D） |
| D3 | 速報の実行場所 | **案 B（CPU 専用の別スレッドで並列）を第一候補とし、T182 の実測で案 A（GPU で確定パスと直列）と比べて決める。** 合否の線は ADR-0007「決定」の表 |
| D4 | 速報と確定の対応づけ | **音源ごとの絶対サンプル位置（16kHz 換算の累計）＋セッション ID。** チャンクの連番は使わない — 20 秒上限・ギャップ分割・遅延時の溜まり方で切れ目が変わり、速報の範囲と一致しないため |
| D5 | 確定の通知 | 確定パスは**チャンクを処理し終えるたびに**、音源・終端位置・セッション ID を通知する。**0 行・キャンセル・例外で終わったときも通知する**（通知しないと、そこまでの速報が消えずに残る） |
| D6 | 速報の出し方 | 文字起こしウィンドウの行一覧の**下に高さ固定の字幕帯**を足し、速報を最大 4 件、薄い斜体で出す。確定の通知が届いたら、その位置までの速報を消す。**行一覧の中で差し替えない**（REQ-LIVEVIEW-04 / 06 / 07 / 09 と衝突するため。ADR-0007 決定 3） |
| D7 | 出力ファイル | **`.txt` に書くのは確定パスの行だけ。** 書式（REQ-TRX-07）・追記のタイミングは今と同じ。速報は一度も書かないので、後から書き換える仕組みは作らない。停止時に「打ち切り」を選んだ区間は今と同じくファイルに残らない（速報は画面にだけ残る） |
| D8 | 停止の順序 | **速報を先に止める**（キャンセル → `StopCancelTimeout` まで join）。その後で確定を従来どおり上限なしで吐き切る。ワーカーが生きていれば processor を破棄しない（T117 の規則を速報にも適用）。停止が完了したら字幕帯を空にする |
| D9 | 速報の区切り | **句単位。** 句は、最初の有声窓の 0.2 秒前から始まる。末尾に 0.6 秒以上の無音が来るか、8 秒に達したら閉じて次の句へ移る。呼び出すたびにデコードするのは**今の句だけ**（発話全体を毎回やり直さない）。末尾の無音は削ってから渡す（無音は定型の幻聴を生むため）。前回の呼び出しから新しい有声が 0.3 秒未満なら呼ばない。句が 1 秒未満なら呼ばない |
| D10 | 速報の Whisper 設定 | greedy・温度 0・温度フォールバック無し（`WithTemperatureInc(0)`）・単一セグメント・トークン数の上限（`WithMaxTokensPerSegment`）。`audio_ctx`（`WithAudioContextSize`）は「窓の長さ＋ 1 秒」を 50 フレーム/秒で換算し、段階に切り上げる（上限 1500）。**この値より長い音声は黙って切り捨てられる**ので、必ず窓より長く取る。質が落ちすぎる場合は 1500 固定に戻す（T182 の M1 / M2 で決める） |
| D11 | 幻聴の除去 | 空文字、同じ語句の繰り返し、無音で出やすい定型句（「ご視聴ありがとうございました」の類）の速報は捨てる。**確定パスの行には適用しない**（確定の出力は今と同じに保つ） |
| D12 | 速報の間隔 | 既定 1 秒。処理時間の割合（duty）に上限を置き、超えたら間隔を伸ばす。マイクとスピーカーは 1 つの予算を分け合う（イヤホンを使わないとマイクも相手の声を拾うため、2 音源で同じ文を 2 回デコードしうる）。どの音源に速報を出すかを隠し設定で選べるようにする |
| D13 | 確定パスの文脈 | 利用者の選択（2026-09-27）: **用語集＋直前の確定文**をプロンプトに渡す。組み立ては「用語集（先頭）＋両音源の直近の確定文を時刻順に並べた末尾約 100 字」。whisper.cpp はプロンプトが長すぎると**先頭から**切るので、用語集にも上限を置く。録音開始と 30 秒以上の無音でリセットする。繰り返しなど壊れた確定行は入れない。確定の呼び出しのたびにプロンプトを組んで processor を作る（Whisper.net 1.9.0 は呼び出しごとにネイティブ状態を作り直すので、processor の生成は軽い）。**採否と既定値は T182 の A/B（M6）で決める** — 誤りが次の文へ伝わるリスクがあるため |
| D14 | 用語集の適用範囲 | **ライブの確定パスだけ。** 速報には渡さない（プロンプトのデコード分だけ速報が遅くなるため）。ファイル文字起こしへの適用は本機能に含めない |
| D15 | 速報用モデルの読み込み | 確定用モデルと同じく**録音していないとき**に、確定用モデルの後に順番に読み込み、常駐させる。GPU 判定のネイティブログ観測はプロセス全体で 1 つなので、読み込みを重ねない。モデル管理で名前を変えたら追従し、削除したら選択を外して速報を無効に倒す（`FileWhisperModelName` と同じ扱い） |
| D16 | 設定 | 設定ウィンドウに出すのは**速報の有効化（既定 OFF。T182 の合格後に見直す）・速報用モデル・用語集**の 3 つ。区切りや間隔などの調整値は `settings.json` だけで変えられる。**計測ログ**（呼び出しごとの所要時間など数値だけ。文字起こしの本文は含めない）も隠し設定で有効にする |
| D17 | 性能の確かめ方 | Zoom 会議中の実機計測で、ADR-0007 の合格線を満たすこと。このクラウド環境には dotnet も GPU も無いため、計測は利用者の手元（RTX 3050 / Vulkan）で行う（T182） |
| D18 | タスクの分け方 | §7 のとおり 8 件に分ける。1 タスク 1 ブランチ |

## 8. テスト一覧

本タスクではテストを追加しない（ソース無変更）。後続タスクで、次の純粋関数（`internal static`）をテストする見込み。

- **`PlanProvisional_*`** — 句の開始・閉じる条件・末尾無音の削り・新しい有声 0.3 秒未満で呼ばない・句の先頭がすでにチャンクに切り出された場合
- **`AudioContextFor_*`** — 窓＋ 1 秒を段階へ切り上げる・上限 1500・最小値
- **`NextProvisionalInterval_*`** — duty の上限で間隔が伸びる・2 音源で分け合う・上下限
- **`SanitizeProvisionalText_*`** — 空・繰り返し・定型の幻聴を捨てる
- **`ApplyProvisionalUpdates_*`**（ViewModel） — 同じ句の更新は上書き・確定の位置より前の速報を消す・位置をまたぐ速報は残す・古いセッションの通知を捨てる・最大件数
- **`BuildContextPrompt_*`** — 用語集が先頭・確定文は時刻順で末尾を残す・壊れた行を除く・リセット条件

> **テストで守れない範囲:** 速報の遅れ、Zoom 会議中の GPU・CPU の取り合い、Vulkan / CPU の並列実行でクラッシュしないこと、
> 速報の日本語の質。いずれも T182 の実機計測で確かめる。

## 9. 未解決の質問

1. **速報を既定で ON にするか** — 選択肢: 既定 OFF のまま / 合格後に ON。*既定案: T182 で合格したら ON に変える。それまでは OFF。*

## 10. 前提

- 速報のエンジンに Whisper の tiny / base を使い、CPU で 1 秒あたりに間に合う速さが出ること（T182 の M1 で確かめる。出なければ案 A、それも駄目なら ADR-0007 案 D を再提案）。
- Whisper.net 1.9.0 の `WithAudioContextSize` / `WithPrompt` / `WithTemperatureInc` / `WithMaxTokensPerSegment` / `WithSingleSegment` が使えること（ソースで確認済み）。
- `WhisperFactoryOptions.UseGpu = false` の CPU コンテキストを、Vulkan の GPU コンテキストと別スレッドで同時に動かしても落ちないこと（T182 の M3 で確かめる）。
- T183（遅れているときの抑止が効かない）は、Zoom 中の遅れの計測結果に影響しうる。T182 の M5 はこれを踏まえて読む。

- **スレッドモデル:** 案 B なら専用スレッドが 1 本増える（ADR-0007）。

- **後方互換:** `settings.json` に新しいキーが増えるだけ。無い場合は既定値（速報は無効）で読み込まれ、今と同じに動く。
