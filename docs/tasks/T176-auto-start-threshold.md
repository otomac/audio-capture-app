# T176 — 自動録音開始の既定値を見直す（−15 dB / 累積 1 秒）

> **状態:** 完了 — 2026-09-23
> **台帳:** [docs/tasks/backlog.md](./backlog.md)
> **前提:** [T168](./T168-auto-start-recording.md) で自動開始を実装した。既定は −30 dB / 3 秒**連続**だった。

## 1. 利用者の指摘（2026-09-23）

- 3 秒しゃべり続けるのはキツい
- −30 dB は割と静かで、周囲の雑音があるレベルでも達成してしまうのではないか
- **−15 dB 以上を 1 秒以上続けたら開始ではどうか**

## 2. 実測（このアプリで録音した実会議。50ms 窓で本体と同じ式で dB 化）

### 2-1. レベルの分布

| 音声 | 中央値 | 90% 点 | −30 dB 以上 | −20 dB 以上 | −15 dB 以上 |
|---|---|---|---|---|---|
| 62.7 分の会議 | −22.9 dB | −10.9 dB | **63.0%** | 42.1% | 26.0% |
| 15.8 分の会議 | −14.8 dB | −5.9 dB | **79.3%** | 64.0% | 50.7% |

**指摘のとおり −30 dB は緩すぎる。** 発話していない時間帯も含めて 6〜8 割の窓が超えており、閾値として働いていない。

### 2-2. 「連続」で数えると、実際には発火しない

62.7 分の会議で、閾値を**連続**で超え続ける時間:

| 閾値 | 回数 | 中央値 | 90% 点 | 最長 | 1 秒以上 | 3 秒以上 |
|---|---|---|---|---|---|---|
| −30 dB | 5,302 | 0.30 秒 | 1.00 秒 | 4.65 秒 | 579 回 | **6 回** |
| −20 dB | 7,611 | 0.15 秒 | 0.45 秒 | 1.80 秒 | 45 回 | 0 回 |
| −15 dB | 6,665 | 0.10 秒 | 0.30 秒 | 1.35 秒 | **4 回** | 0 回 |

**発話は語と語の間で必ずレベルが落ちる。** したがって「連続」で数える限り、
提案の −15 dB / 1 秒は 1 時間で 4 回しか成立せず、**実質的に発火しない**。
現行の −30 dB / 3 秒も 6 回しかなく、同じ問題を抱えていた（T168 の単体テストは一定レベルを与えていたため気づけなかった）。

### 2-3. 落ち込みを許容して「累積」で数えた場合（62.7 分の会議、先頭 10 分）

| 閾値 | 累積 | 落ち込み許容 | 初回の発火 | 10 分あたりの成立 |
|---|---|---|---|---|
| −30 dB | 3.0 秒 | なし（現行） | 64.1 秒 | 3 回 |
| −15 dB | 1.0 秒 | なし（提案のまま） | 23.8 秒 | 2 回 |
| **−15 dB** | **1.0 秒** | **0.3 秒** | **13.7 秒** | **75 回** |
| −15 dB | 1.0 秒 | 0.5 秒 | 6.2 秒 | 108 回 |
| −20 dB | 1.0 秒 | 0.3 秒 | 5.7 秒 | 181 回 |

## 3. 決定事項

| # | 決定 | 結論 |
|---|---|---|
| D1 | 閾値 | **−15 dB**（提案どおり）。2-1 のとおり −30 dB は雑音レベルと区別できていない |
| D2 | 継続時間 | **1.0 秒**（提案どおり）。ただし**「連続」ではなく「累積」**にする |
| D3 | 落ち込みの許容 | **0.3 秒**を新設（`AutoStartDipGraceSeconds`）。2-2 のとおり許容なしでは発火しない。0.5 秒より 0.3 秒を採るのは、連続した打鍵音などが 1 秒ぶん積み上がるのを避けるため |
| D4 | 発火しない環境への逃げ道 | 閾値を `settings.json` で −20 へ下げられる（実測で発話開始から 5.7 秒）。設定ウィンドウの説明文にも書く |
| D5 | 誤起動の抑止 | 許容を超える落ち込みで累積を 0 に戻す（咳・単発のクリック音では起動しない）。`canStart` が false の間は累積も落ち込みも 0 に戻す |

## 6. テスト一覧

- **`Observe_ShortDipWithinGrace_KeepsAccumulating`** — 0.5 秒発話 → 0.2 秒の切れ目 → 0.5 秒発話 で発火する
- **`Observe_DipLongerThanGrace_ResetsAccumulation`** — 0.35 秒の落ち込みで累積を捨てる
- **`Observe_CannotStart_ResetsBothCounters`** — 条件が整った瞬間に以前の積算で即発火しない
- **`AutoStartOptions_Defaults_MatchMeasuredValues`** — 既定が −15 dB / 1.0 秒 / 0.3 秒であること
- **`AutoStartOptions_ClampsAndFallsBack`** — 落ち込み許容も含めてクランプ・既定へのフォールバック

## 7. 確認（本体の判定器をそのまま実会議の音声に通した）

| 音声 | 初回の発火 | 全体の成立回数 |
|---|---|---|
| 62.7 分の会議 | **13.7 秒** | 339 回 |
| 15.8 分の会議 | **3.0 秒** | 337 回 |

> **注意（未検証）:** 上の音声は録音された **`.mp3`（マイクとスピーカーのミキシング後）** のレベルであり、
> 自動開始が実際に見るのは**マイク単独のモニタ値**である。マイクの音量設定や距離によっては −15 dB に届かないことがある。
> そのときは `AutoStartThresholdDb` を −20 程度へ下げる（D4）。
> なお計測時、既定のマイク（Brio 300）は **OS 側でミュート**されていたため、周囲雑音の実測はできていない。
