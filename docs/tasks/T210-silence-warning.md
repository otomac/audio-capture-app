# T210 — 録音中に無音が続いたら警告ダイアログを出す

> **状態:** 完了 — 2026-11-23
> **台帳:** [docs/tasks/backlog.md](./backlog.md)

## 1. 目的

デバイスの選び間違い・ミュートのまま・録音の途中でデバイスから音が来なくなった、に気づかないまま会議を録り終えるのを防ぐ。
槇さんの要望 (2026-09-29)「録音開始後 1 分以上無音が続いたら警告ダイアログを表示する」。

## 2. スコープ境界

**やること**
- 録音中、マイクとスピーカーの両方が無音のまま 60 秒続いたら警告ダイアログ（OK のみ）とステータスバーで知らせる
- 秒数としきい値を `settings.json` で変えられるようにする（UI は作らない）

**やらないこと（重要）**
- **録音は止めない・自動で何かを切り替えない**（警告するだけ）
- **デバイスが死んだときの張り直しはしない**（T164 の範囲）
- **自動開始の判定器（REQ-REC-12）には触らない**（同じ経過時間の数え方の問題は T214 として起票）

## 3. 決定事項

| # | 決定 | 結論 |
|---|---|---|
| D1 | 何を無音とみなすか | **マイクとスピーカーの両方**が −50 dB 未満。台帳の既定案どおり両方。録音ファイルはこの 2 つを混ぜたものなので、片方が鳴っていれば空ではない |
| D2 | しきい値 | **−50 dB。** 台帳の既定案（自動開始と同じ −15 dB）は採らなかった。−15 dB は「声がある」の線で、会議の 74% の窓が下回るため。実測（下表）で普通の会議は −50 dB 未満が 60 秒続かない |
| D3 | いつ見張るか | **録音中ずっと。** 台帳の既定案「録音開始後の 1 回だけ」は採らなかった。実測で、**始まって 31 分は録れていて、そこから 73 分が無音**だった録音（2026-10-30）が見つかり、開始直後だけ見ていてはこれを捕まえられない |
| D4 | 何回出すか | **1 回の無音につき 1 回。** どちらかがしきい値以上になったら次の無音に備える |
| D5 | 録音を続けるか | **続ける**（台帳の既定案どおり） |
| D6 | 経過時間 | **実時間で測る**（1 回 1 秒まで）。名目の 50ms を足すと、10 秒の設定が 12.8 秒になった |
| D7 | ダイアログの出し方 | VM はイベント（`SilenceWarningRequested`）を上げるだけで、View が `Dispatcher.BeginInvoke` で MessageBox を出す。メーターのタイマーの中で入れ子のメッセージループを回さないため |

### 実測（このアプリの録音 6 本、50ms 窓のピークを本体と同じ式で dB 化。集計の数字のみ）

| 録音 | 長さ | −50 dB 未満が続いた最長 | −45 dB 未満 | −40 dB 未満 |
|---|---|---|---|---|
| 会議 (08-29) | 62.7 分 | 4.5 秒 | 4.5 秒 | 5.8 秒 |
| 配信 (09-27) | 12.3 分 | 0.7 秒 | 0.7 秒 | 0.8 秒 |
| **会議 (10-30)** | 104.2 分 | **4,375 秒（31 分の時点から終わりまで）** | 4,375 秒 | 4,382 秒 |
| 配信 (11-08) | 85.0 分 | 14.1 秒 | 14.1 秒 | 14.1 秒 |
| 試し録り (11-21) | 0.1 分 | 1.2 秒 | 1.9 秒 | 2.0 秒 |
| 会議 (11-21) | 61.2 分 | 9.2 秒 | 28.7 秒 | 30.9 秒 |
