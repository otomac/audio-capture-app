# アーキテクチャ決定記録（ADR）

アーキテクチャに関わる決定を、**実装より先に** ここへ記録する
（[法 3 — アーキテクチャ優先](../harness/00-ways-of-working.md#法-3--アーキテクチャ優先)）。

## 使い方

1. ファイル名は `NNNN-<slug>.md`（`0002-introduce-di-container.md` 等）。番号は連番、再利用しない。
2. 様式は [docs/harness/templates/adr.md](../harness/templates/adr.md)。
3. **承認を得てから実装する。** ADR なしの構造変更は差し戻し対象。
4. 決定を覆すときは既存 ADR を書き換えず、**新しい ADR を書いて「置換済み」にする**。

## ADR が必要になる変更

- 層の追加・削除、依存方向の変更
- DI コンテナの導入
- `MainViewModel` の分割
- Service 層へのインターフェース抽象の導入
- 新しい外部ライブラリの採用
- スレッドモデルの変更

迷ったら：*「3 か月後の担当者が『なぜこうなっている？』と聞きそうか？」* → Yes なら書く。
