# ADR-0004 — 話者 ID の付け方を sherpa-onnx に任せ続ける（自前クラスタリングは今回採らない）

> **状態:** 承認済み（2026-08-23・利用者による）— 決定は「現状維持」であり、本 ADR によって
> 現在の実装は 1 行も変わらない。**承認されたのは「今は案 A を採り、案 C は条件付きで T148 へ送る」という判断そのものである。**
> 案 C を実装してよいのは、下の「案 C を採用してよい条件」3 つがすべて揃ったときに限る（→ T148）。
> **日付:** 2026-08-23
> **関連タスク:** [T146](../tasks/T146-short-segment-embedding.md)（本 ADR の起票元）／
> [T138](../tasks/T138-speaker-id-fragmentation.md)／[T142](../tasks/T142-diarization-attribution-root-cause.md)／
> [T147](../tasks/T147-known-speaker-count-in-dialog.md)
> **前提となる ADR:** [ADR-0003](./0003-speaker-diarization-with-sherpa-onnx.md)（争点 1 の再検討にあたる）

## 背景

同一人物の話者 ID が複数に割れる（T115 → T138）。T146 で**原因を直接測って確定させた。**

- **話者埋め込みは切り出しが短いほど「同一人物を同一と認める力」を失う。**
  同一話者どうしのコサイン類似度は 0.25 秒で 0.31、1 秒で 0.51、3 秒で 0.76、10 秒で 0.90。
  別話者どうしは長さによらず 0.22〜0.44 のままである（T146 §7-1）。
- **既定のクラスタリング閾値 0.5 は、ちょうど「1 秒の区間の同一話者類似度」と同じ高さにある。**
  実際の話者区間は中央値 1.03 秒・半数が 1 秒未満（T138 §7-3）なので、
  **同一人物の区間の約半分が閾値を越えられない。** これが断片化の機構である。
- sherpa-onnx の `OfflineSpeakerDiarization` は
  **「区間を切る」「埋め込みを取る」「クラスタリングする」を 1 つの `Process` に閉じ込めている。**
  外から触れるのは `Threshold` と `NumClusters` だけで、**どちらも断片化に効かない**
  （閾値は T138 で 0.4〜0.7 を実測、`NumClusters` は T147 で有害と確定）。

したがって「今のまま設定で直す」道は閉じている。**構成そのものを変えるかどうかの判断が要る。**
ADR-0003 争点 1（Diarization エンジンをどう調達するか）の再検討にあたるため ADR を置く。

## 現状

- [ADR-0003](./0003-speaker-diarization-with-sherpa-onnx.md) 争点 1 案 A により、
  `SpeakerDiarizationService` が `OfflineSpeakerDiarization.Process` を呼び、
  **話者区間（開始・終了・話者 ID）をそのまま受け取っている。**
- ID の意味づけ（同一 ID＝同一話者）は **完全に sherpa-onnx の内部実装に依存**している。
- 統合（どの行がどの話者か）だけが自前（`TranscriptDiarizationMerger`、`internal static` の純粋関数）である。
- 出力の読み方の制約は要求仕様 §13 に明記済み（**話者 ID を人物の一意な識別子として扱わない**）。

## 選択肢

### 案 A — 現状維持（採用）

- **内容:** sherpa-onnx が返す話者 ID をそのまま使い続ける。制約は仕様と README に書いてある。
- **利点:** 追加の実装が無い。今の挙動が既に利用者の手元にあり、再検証の費用が発生しない。
  誤りの出方（ID が増える）は**目に見える**ので、利用者が疑ってかかれる。
- **欠点:** 会議 15 分で 36〜72 種の ID が行に付く。議事録生成の後段で人物をまとめる作業が残る。
- **影響範囲:** なし。

### 案 B — sherpa-onnx の出力を後処理して短い区間の ID を寄せる

- **内容:** `TranscriptDiarizationMerger` の手前に純粋関数を 1 つ足し、
  一定長未満の区間の ID を隣接する区間の ID へ付け替える。
- **利点:** 実装が小さく（純粋関数 1 つ）、テストしやすく、いつでも外せる。依存は増えない。
- **欠点:** **効かない。** 安全な範囲（1 秒未満まで）では行に付く ID が会議 A で 72 → 70 しか減らず、
  正答率も 92.0% → 92.2% と誤差の範囲（T146 §7-3）。
  効く設定（1.5 秒以上を寄せる）は基準音声の区別を 4/4 → 2/4 に壊す。
- **影響範囲:** Services 層に純粋関数 1 つ。
- **却下する。** 得るものが小さすぎる。

### 案 C — 区間の時刻だけを sherpa-onnx から受け取り、ID の決定を自前で行う

- **内容:** `Process` の結果から**時刻だけ**を使い、各区間の埋め込みを
  `SpeakerEmbeddingExtractor`（sherpa-onnx の既存 API。**依存は増えない**）で取り直し、
  **3 秒以上の区間だけで凝集型クラスタリング**（平均連結・コサイン類似度 0.60 で打ち切り）を行う。
  3 秒未満の区間はクラスタを作る権利を持たず、できた重心のうち最も近いものへ寄せる。
- **利点:** **測った範囲では明確に良い**（T146 §7-4）。
  - 基準音声（正解の分かる 4 箇所）: 使用 ID **6 → 2**（実際の人数）、区別は **4/4 のまま**
  - 合成音声（正解が全区間で既知）: 3〜4 ID → **2 ID**、正答率 92.0% → **92.4%** / 97.5% → 97.5%
  - 単独話者の録音 2 本: **1 人のまま**（壊れない）
  - 会議: 使用 ID 72 → 20 / 36 → 13
  - 処理時間の増加は約 1 割（15 分 47 秒の会議で +12 秒）
  - **T115 以降で「ID の数」と「区別」が同時に良くなった初めての構成である。**
- **欠点:**
  - **しきい値の安全域が狭い。** 実測 6 本で安全に切れる範囲は類似度 0.53〜0.65 の幅 0.12 しかなく、
    採用値 0.60 の余裕は上側 0.053・下側 0.068（T146 §7-4）。
  - **外したときの壊れ方が非対称で沈黙的。** 高すぎれば ID が増えるだけ（今と同じ）だが、
    低すぎると**全員が 1 人にまとまる**。実際 0.50 では合成音声が 1 ID・正答率 52% に潰れた。
    利用者からは「うまくまとまった」ようにしか見えない。
  - **判断の材料が足りない。** 正答率を測れるのは合成音声だけで、その合成音声は
    別々の録音をつないだものである（録音条件の違いが話者の違いとして働いている可能性が残る）。
    本物の音声で正解があるのは基準音声 1 本の 4 箇所だけである。
  - Services 層にクラスタリングのアルゴリズムを抱えることになる（約 150 行）。
    ADR-0003 案 B（自前実装）を「実装量と正しさのリスクが規模に見合わない」として却下した
    判断の一部を、範囲を限って覆すことになる。
- **影響範囲:** `SpeakerDiarizationService`（埋め込み抽出の追加）、Services 層に純粋関数 1 つ、
  要求仕様 §13、README、テスト。

### 案 D — Diarization エンジンごと差し替える（pyannote.audio 4.0 / community-1 など）

- **内容:** 2026 年 8 月時点の最新は pyannote.audio 4.0 ＋ community-1。
- **利点:** 精度の実績がある。重なった発話の扱いも改善しているとされる。
- **欠点:** **ADR-0003 争点 1 案 C で却下した理由がそのまま生きている** — Python ランタイムの同梱が要り、
  単体 exe で完結する配布形態が崩れる。ONNX 化して sherpa-onnx から使う道は、
  **sherpa-onnx の配布モデルに追加されていない**（2026-08-23 時点で
  `speaker-segmentation-models` リリースの資産は 2024-12-15 以降更新なし。T144）。
- **却下する。** 配布形態の変更に見合う根拠が無い。

### 案 E — 何もせず、より強い埋め込みモデルを既定にする

T138 で実測済み。ResNet293 は会議の ID を 7〜11 種まで減らすが、
**正解の分かる音声では区別を落とし**、処理時間が実時間の 1.4〜1.7 倍になる。**却下済み。**

## 決定

**案 A（現状維持）を採る。案 C は「有望だが今回は採らない」として保留し、T148 で扱う。**

決め手：

1. **案 C の効果は本物に見えるが、それを裏づける材料が 1 本の実音声（の 4 箇所）と
   3 本の合成音声しかない。** 本プロジェクトはこれまで 2 度（T138・T142）、
   「見た目が良くなる変更」を**正解の分かる材料で確かめられないという理由で**見送っている。
   同じ基準を案 C にも適用する。
2. **壊れ方が沈黙的である。** 今の断片化は「ID が多い」という形で利用者から見える誤りだが、
   案 C の失敗は「全員が 1 人にまとまる」という形で、**正しく動いた場合と区別が付かない。**
   安全域 0.12 という測定結果は、この失敗が現実に起こりうることを示している。
3. **急ぐ理由が無い。** 案 C はいつでも足せる（sherpa-onnx への依存の形は変わらない）。
   材料を増やしてから決めるほうが安い。

**この決定は ADR-0003 を変更しない。** 争点 1 案 A（sherpa-onnx の公式 API を使う）、
争点 2 案 A（ファイル文字起こし経路のみ）、争点 3 案 A（インターフェース抽象を作らない）は
いずれもそのままである。

### 案 C を採用してよい条件（T148 の完了条件）

次の 3 つが揃ったら採用してよい。1 つでも欠けるなら採用しない。

1. **正解の分かる材料を増やす。** 少なくとも
   **本物の多人数会議 1 本について、参加人数と主要な話者交代の正解**を用意する
   （利用者による申告でよい。全区間の正解までは要らない）。
2. **しきい値を固定値で持たない設計にする。** 実測では同一話者の併合は 0.65 以上、
   別話者の拒否は 0.53 以下で起きており、**両者の間には 0.25 以上の段差がある。**
   固定値ではなく**段差の位置で切る**（併合の類似度が急落した点で打ち切る）ほうが、
   音声ごとの絶対値の違いに強い。この設計を実測で確かめること。
3. **潰れたことを検出して知らせる。** 「全員が 1 人にまとまった」ときに
   利用者が気づけること（例: 使用 ID が 1 種になった場合の警告、または付け直し前の ID 数の併記）。

## 結果

- **良くなること:**
  - 断片化の**機構が数で確定した**。以後の議論は「なぜ割れるのか」ではなく
    「どの長さの区間を信じるか」という具体的な設計問題になる。
  - 案 C の実装方針・パラメータ・期待効果・失敗の形が、実測値付きで残った。
    採用の判断は T148 で 1 ステップでできる。
- **悪くなること・受け入れるコスト:**
  - **会議の話者 ID は当面 36〜72 種のままである。** 議事録生成の後段で人物をまとめる作業が残る。
  - 測って良いと分かったものを、材料不足を理由に見送っている。
    **もし T148 で採用されるなら、その間の出力は改善できたはずのものだった**ことになる。
- **後戻りのしやすさ:** 高い。何も変えていない。
